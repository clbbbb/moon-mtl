# 输入、逻辑语义与资源边界

设观测序列为 `(t_i, v_i)`，时间戳满足 `0 ≤ t_0 < t_1 < … ≤ Int64.max`。命题只在记录位置上取值。两个相邻位置之间没有隐含观测，也没有信号保持假设。所有窗口均为闭区间 `[a,b]`，要求 `0 ≤ a ≤ b`。

| 公式 | 在位置 i 的含义 |
|---|---|
| `previous p` | i > 0 且 p 在 i−1 成立；初始位置为 false |
| `once[a,b] p` | 存在 j ≤ i，a ≤ t_i−t_j ≤ b，且 p 在 j 成立 |
| `historically[a,b] p` | 所有满足窗口条件的 j 都满足 p；没有此类 j 时为 true |
| `p since[a,b] q` | 存在窗口内 j，q 在 j 成立，且 p 在每个 j < k ≤ i 成立 |

Since 不要求左式在见证位置 j 成立。因此，左式当前为假但右式当前为真时，`since[0,b]` 仍可成立；旧见证会被清除。窗口下界大于零时，新候选先保存，达到下界后才可作为见证。

优先级从高到低为：一元运算、since、`&`、`|`、`->`。Since、与、或左结合；蕴含右结合。标识符首位为 ASCII 字母或下划线，后续允许字母、数字、下划线和点，最长 128 字符。关键字不能作为命题。语法错误偏移按 Unicode 标量计数；输入长度预算按 UTF-16 单元计算。

## 队列算法

每个时序节点维护按时间排序的候选队列。Once 入队子式为真的位置，Historically 入队子式为假的位置，Since 入队右式为真的位置，并在左式为假时清除旧位置。首先丢弃年龄大于上界的候选；若最早剩余候选已达到下界，即存在合格候选。

每个候选入队一次、过期或清除一次。过期查找对无过期、一个过期和全部过期采用快速路径，对大量部分过期采用二分下界查找，避免单次时间跳跃扫描整个队列；回收仍可能复制活跃后缀。每次 push 还要处理全部 DAG 节点、校验所需命题，因此不声称单条操作严格常数时间。节点值采用双缓冲，队列头和新增候选暂存数组复用；返回的决策仍持有独立结果，不会被后续更新修改。计划另存时序节点列表，提交阶段只遍历这些节点。计划编译用哈希表检测重复命题和规则名，并设置语法遍历预算防止指数展开。

时间窗有限不代表事件数有限。密集采样仍可能产生大量候选，所以库另设候选数量预算。`retained_candidates` 统计逻辑活跃条目，并非进程堆字节。物理队列有回收余量；测试检查其长度不超过 `2 × 活跃条目 + 64`。对象、数组、暂存空间和运行时开销不包含在该统计中。

## 默认预算

| 项目 | 默认值 | 可配置上限 |
|---|---:|---:|
| DAG 节点 | 512 | 4096 |
| AST 深度 | 64 | 128 |
| 活跃候选总数 | 65536 | 1000000 |
| 接受的事件数 | 1000000 | 1000000000 |
| 一次参考解释工作量 | 1000000 | 100000000 |

参考解释器每次递归调用消耗一步。Decision 校验共享一次参考执行预算；Evidence 校验的全部片段共用 1,000,000 步，超预算返回错误而不是错误 verdict。输入最多包含 4096 个布尔命题，公式文本最多 16384 UTF-16 单元，JSON 最多嵌套 16 层且拒绝重复键。

## 提交与错误

Monitor.push 的输入、时间戳、事件数、候选数错误均发生在提交前，可以修改输入后用同一时间戳重试。离线 Reference 会验证整个输入序列，所以即使评估前缀，非法后缀仍会导致构造失败。

Monitor.replay_jsonl 是整批字符串便利接口，最多 16 MiB；逐行提交，遇错保留已接受前缀。JsonlSession 是增量字符串接口，错误后永久关闭。两者对空批次、尾部换行和空行的规则一致：空批次允许、一个尾部换行允许、空记录拒绝。命令行当前读取完整文件并检查长度，不能视为有严格读前内存上限的文件流工具。

Formula.format 生成优先级明确的规范文本，并验证输出在指定解析预算内可重读；展开共享语法超过预算时返回错误。Plan.to_json 输出文本规则，接收端始终按自己的预算重新解析；非常大的手工 AST 可能需要扩大接收预算，不能把发送端计划视为绕过验证的凭据。
